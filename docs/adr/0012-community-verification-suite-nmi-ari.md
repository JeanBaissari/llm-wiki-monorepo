# ADR 012: Community Verification Suite — NMI/ARI Cross-Validation

- **Status:** accepted
- **Date:** 2026-07-04
- **Context:** The wiki has two independent implementations of the Louvain community detection algorithm: TypeScript (via `graphology-communities-louvain` in the graph-engine) and Python (native implementation in `src/llm_wiki/louvain.py`). Both must produce substantially identical community assignments for the same input graph, or the insights and visualizations derived from them will be inconsistent. A one-off manual comparison is insufficient — this check must be automated for CI.
- **Decision:** A dedicated verification suite (`verify-communities.yml` GitHub workflow) runs on every push and PR to main. It generates 7 graph topologies (planted partition, random, star, grid, hierarchical, complete, noise-only) across 5 random seeds — 35 distinct test cases. Both TypeScript and Python implementations run the same inputs. The Normalized Mutual Information (NMI) and Adjusted Rand Index (ARI) are computed between the two output labelings. The pass threshold is NMI/ARI > 0.95. The Python implementation uses deterministic shuffling (seed=42) and maintains Σ_in/Σ_tot accounting for modularity tracking. Community IDs are renumbered by size (0 = largest) before comparison to ensure labeling-independent matching.
- **Consequences:** Easier: CI catches regressions in either implementation automatically. 35 test cases give high confidence (7 topologies × 5 seeds). The Σ_in/Σ_tot tracking also prepares the Python code for future multi-level (Phase 2) Louvain. Harder: the workflow adds ~2 minutes to CI time. The 0.95 threshold allows minor floating-point divergence but could mask subtle differences in tie-breaking on certain graph structures.
